# Analysis and Discussion

This document addresses the open questions from the NLP Home Assignment, providing a detailed analysis of the retrieval methods, potential improvements, and considerations for ground truth creation.

## Potential Improvements for Retrieval Using an LLM

### For Lexical Retrieval:

1. **Query Expansion**:
   - LLMs can expand user queries with synonyms and related terms to bridge the lexical gap.
   - Example: A query for "Harry's wand" could be expanded to include "Harry Potter's magic stick", "wizard's tool", etc.
   - This helps overcome the vocabulary mismatch problem inherent in TF-IDF.

2. **Re-ranking**:
   - Use an LLM to re-rank TF-IDF results based on semantic relevance.
   - The initial retrieval can use fast TF-IDF, then an LLM can analyze the top-k results to provide a more semantically meaningful ranking.

3. **Document Expansion**:
   - Enrich documents with related terms generated by an LLM before indexing.
   - This creates a more comprehensive representation of each document, increasing the chance of lexical matches.

### For Semantic Search:

1. **Hybrid Retrieval**:
   - Combine lexical and semantic approaches, using LLMs to determine optimal weighting.
   - LLMs can analyze queries to decide whether lexical or semantic features should be prioritized for a particular query type.

2. **Query Understanding**:
   - LLMs can better understand the intent behind queries, especially for complex or ambiguous queries.
   - They can reformulate queries to better match the retrieval system's capabilities.

3. **Context-Aware Embeddings**:
   - Generate embeddings that consider the broader context of the document.
   - LLMs can create embeddings that capture not just the local meaning of a passage but its role in the broader narrative.

4. **Domain Adaptation**:
   - Fine-tune embeddings for specific domains (like Harry Potter or cyber security).
   - An LLM can be fine-tuned on domain-specific data to create more relevant embeddings.

### For Both:

1. **Relevance Feedback**:
   - Incorporate user feedback to improve future retrievals.
   - LLMs can learn from user interactions to refine retrieval strategies over time.

2. **Multi-hop Reasoning**:
   - Enable retrieving information that requires connecting multiple passages.
   - LLMs can perform reasoning over multiple retrieved passages to answer complex queries.

3. **Explainability**:
   - LLMs can explain why certain passages were retrieved, improving user trust.
   - This helps users understand the system's decisions and potentially refine their queries.

## Drawbacks and Limitations

1. **Computational Cost**:
   - LLMs are resource-intensive, making real-time retrieval challenging.
   - The latency introduced by LLM processing may be prohibitive for applications requiring immediate responses.

2. **Hallucination Risk**:
   - LLMs might generate plausible but incorrect information.
   - When used for query expansion or document enrichment, hallucinations could introduce noise into the retrieval process.

3. **Training Data Bias**:
   - LLMs may inherit biases from their training data.
   - This could lead to systematically biased retrieval results, particularly for queries related to sensitive topics.

4. **Lack of Transparency**:
   - The "black box" nature of LLMs makes it difficult to understand why certain results are returned.
   - This can make debugging and improving the system challenging.

5. **Contextual Limitations**:
   - Current models have token limits that restrict the amount of context they can process.
   - This limits their ability to reason over very long documents or large collections of passages.

6. **Evaluation Challenges**:
   - It's difficult to objectively evaluate semantic relevance without human judgment.
   - Traditional IR metrics may not fully capture the quality of LLM-enhanced retrieval.

## Creating a Reliable Ground Truth for Evaluation

Instead of using miniLM results as ground truth, a more reliable approach would be:

### 1. Human Annotation

- Have multiple domain experts (e.g., Harry Potter fans or literature experts) annotate each chunk for relevance to a set of predefined queries.
- This provides a more reliable ground truth than any automated method.

### 2. Annotation Process

- **Define a diverse set of query types**:
  - Factual queries (e.g., "What is the spell to levitate objects?")
  - Character-based queries (e.g., "Describe Hermione's personality")
  - Thematic queries (e.g., "Passages about friendship in Harry Potter")
  - Plot-based queries (e.g., "How did Harry defeat the troll?")

- **Graded relevance scale**:
  - 0: Not relevant
  - 1: Slightly relevant (mentions query terms but not central to the passage)
  - 2: Moderately relevant (addresses part of the query)
  - 3: Highly relevant (directly answers or addresses the query)

- **Inter-annotator agreement**:
  - Calculate metrics like Cohen's Kappa or Fleiss' Kappa to ensure reliability
  - Resolve disagreements through discussion or using a third annotator

### 3. Pooling Method

To make annotation feasible for large collections:

- Run multiple retrieval systems (TF-IDF, BM25, different embedding models)
- Pool the top-k results from each system
- Only annotate the pooled results
- Assume non-pooled documents are not relevant

This is a standard approach in information retrieval evaluation (used in TREC competitions) that makes the annotation task manageable while still providing reliable metrics.

### 4. Contextual Considerations

- Consider annotating not just individual chunks but also their surrounding context
- Relevance might depend on broader narrative context, especially for literary texts
- Create hierarchical relevance judgments that consider both the specific chunk and its context

### 5. Query Variations

- For each core query, create multiple variations with different wording
- This helps evaluate the robustness of retrieval systems to query formulation
- Example: "How did Harry get his scar?" vs. "What caused the lightning mark on Harry's forehead?"

### 6. Balanced Query Set

- Ensure the query set covers different aspects of the book
- Include queries with varying difficulty levels
- Balance factual vs. interpretive queries

By following this approach, we would create a more reliable ground truth that better reflects human judgments of relevance, allowing for more meaningful evaluation of different retrieval methods.
